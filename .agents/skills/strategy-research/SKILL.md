# 量化策略研发流程

前置约束：

1. `AGENTS.md` §1 推断纪律、§2 表述纪律全程生效且优先级最高。
2. 本流程的基础是预注册：所有判定标准必须写在结果产出之前。
3. 留痕位置：`research/prereg/` 存跑结果前冻结的判定标准，`research/decisions/`
   存结果出来后的口径裁定，`research/notes/` 存文献与探索随笔。三者按同一日期前缀成组。
4. 文件名与目录名一律 ASCII（`AGENTS.md` §4.1）；文档正文用中文，代码与注释用美式英文
   （`AGENTS.md` §2.3）。

## 零、本流程的三条不可让渡的纪律

违反任一条，产出即作废，与结论本身的成色无关。

| # | 纪律 | 含义 | 典型违反形态 |
|---|---|---|---|
| P1 | 标准先于结果 | 筛选门槛、采纳规则、判定阈值、怀疑点，全部写定并落盘后，才允许跑实验或看结果 | 跑完回测再定「什么算通过」，等于用结果迁就标准 |
| P2 | 负面结果同样入档 | 被证伪的实验、失败的方向、无显著性的检验，全部保留在预注册文档与结果表中，不删除不淡化 | 只留下活下来的 10 项、删掉被否的 40 项，读者看到的是幸存者偏差 |
| P3 | 缺口如实呈报 | 回测收益与前瞻收益的差距、达不到目标的部分，直接写进正文与摘要，不靠加久期、加杠杆、换口径去凑 | 目标 3% 而前瞻只有 2.7%，为凑数把杠杆上限从 1.3 倍抬到 1.6 倍 |

配套要求：区分「跑通」与「正确」，程序无报错不等于逻辑正确；任何数值带出处
（文件:行号、命令、网页位置）；统计量必须说明口径，即谁的中位数、带符号还是绝对值。

## 一、阶段 0：立项固化

在任何检索和编码之前，把下面四件事落盘到 `<research_dir>/0_task_and_progress.md`。

### 1.1 验收标准逐条抄清

把用户给的每一条要求写成可判定的形式。凡是模糊的，按 `AGENTS.md` §1.2 停下来问，
不要自行取一个「最可能」的解释。

必须问清而不能默认的典型项：

| 项 | 为什么不能默认 |
|---|---|
| 资金规模与容量约束 | 决定是否需要冲击成本测算，决定容量门槛的权重 |
| 收益是费前还是费后 | 直接改变通过与不通过的裁定 |
| 回撤口径（日频或月频、绝对或相对基准） | 同一个 -0.5% 按不同口径可差一倍 |
| 实施初期是否有额外约束 | 例如「前两周净值必须向上」会引出上线协议这一整块设计 |
| 禁用的方法族 | 例如禁用神经网络与机器学习，会直接砍掉一半候选 |
| 与哪些既有策略必须低相关 | 正交性是硬门槛，须先拿到既有策略的收益驱动清单 |

### 1.2 目录骨架（ASCII 命名）

```
<research_dir>/
  0_task_and_progress.md    进度日志，每完成一个阶段追加一行，含时间
  1_literature/             每个候选族一份笔记，编号命名
  2_screening/              screening_criteria.md（预注册）与 screening_matrix.md
  3_data_and_backtest/      venv、可复现脚本、data/、results/
  4_strategy_design/        入选策略详细设计，含参数预注册
  5_adversarial/            adversarial_falsification.md 与每轮探索的预注册与裁定
  6_<topic>/                后续每个新方向单开一个编号目录
  strategy_research_report_*.md   最终交付
```

### 1.3 方法约束声明

只用无需账号权限的公开资料；无实时行情时允许公开历史数据做近似回测，
但须明示口径与局限；结论区分已证实与推断，推断显式标注。

### 1.4 进度日志规则

每个阶段结束追加一行，格式 `- HH:MM 事件`。日志属对外留痕件，按 `AGENTS.md` §2.2 写：
不出现第二人称、不引用交互过程、无 AI 署名。

## 二、阶段 1：候选发散与筛选标准预注册

### 2.1 发散

列出 8 至 12 个候选策略族，覆盖不同收益驱动（期限溢价、曲率、信用、微观结构、
制度性日历、一二级价差、跨市场）。此阶段以覆盖面为先，淘汰在下一步做。

### 2.2 写 `2_screening/screening_criteria.md`（此时结果尚未产出）

三块内容缺一不可。

硬性门槛（任一不过即淘汰，不进入打分）：

| # | 典型门槛 |
|---|---|
| G1 | 方法族合规，例如不用神经网络与机器学习，经典统计允许 |
| G2 | 收益驱动与既有策略不同，逐条对照既有策略的收益本质，同源即判重叠 |
| G3 | 现有交易通道可执行，缺资格的降级为远期储备，不是直接淘汰 |
| G4 | 收益路径清晰、可用规则写出来，说不清收益来源的淘汰 |

打分维度（过门槛者按 0 至 10 分加权）：回撤可控性、收益充足性、低相关性、
实施初期平稳性、文献证据强度、容量与成本。权重按本次验收标准的侧重分配，并写明理由。

预注册的怀疑点：把此刻对每个候选族的怀疑逐条写下，例如「骑乘在当前利率水平下
rolldown 是否仍然足够」「可转债信用冲击下回撤大概率突破限额」。
结果回来后必须逐一核对并回答，不得跳过。这一条是防止事后合理化的主要手段。

## 三、阶段 2：文献调研

### 3.1 并行执行

用 Workflow 或多个 Agent 并行，一个候选族一个 agent。单次并行规模按会话的
workflow size 指引控制。agent 因用量上限失败时，缺口由主会话补查，不得静默留白，
并在进度日志中标注哪几份属补查级。

### 3.2 每份笔记的强制结构

```
- 调研日期 / 定位 / 访问等级标注说明
0. 一句话结论（前置，含评分与定位）
1. 机制与收益分解公式
2. 文献逐篇（标题、作者、年份、URL、access 等级、关键结论）
3. 场所适配性（OKX 与 Trading 212 的制度差异、数据可得性、通道可得性）
4. 对照本次硬性要求的逐条评估
5. 风险点与已知反证
```

### 3.3 访问等级（必标，不得含糊）

| 等级 | 含义 |
|---|---|
| full | 读到全文 |
| abstract | 只读到摘要 |
| secondary | 二手转述，例如搜索引擎摘要、转载页 |
| blocked | 访问失败（403、需登录、UA 拦截），须标明失败形式 |

禁止把 secondary 当 full 使用；blocked 的条目保留在笔记中并注明失败原因，
不得删除后当作未曾查过。

## 四、阶段 3：数据与近似回测

### 4.1 可复现优先

独立 venv；数据抓取脚本与回测脚本分离；原始数据落盘 `data/`，结果落盘 `results/`；
同一脚本重跑必须得到同一结果。

### 4.2 口径声明

回测开头写明：数据源与通道、近似之处（例如零息近似重定价、用某利率代理资金成本）、
代理变量与真实变量的已知偏差方向及量级。

### 4.3 已知易犯错误清单（每次写完回测逐条自查）

| # | 错误 | 症状 | 正确做法 |
|---|---|---|---|
| E1 | 交易成本按日扣 | 整族策略收益全为负，年化凭空少 2% | 只在调仓日扣 |
| E2 | 风控刹车无重入路径 | 触发后策略永久归零，此后年份全平 | 设冷却期、重置峰值、半仓重入 |
| E3 | 前视偏差 | 结果好到不合理 | 代码级核查：所有信号只用 t-1 及更早数据 |
| E4 | 单位或量纲错 | 数量级差 100 或 10000 | 用可判别的实证检验，例如相邻 K 线 ts 差恒等于周期毫秒数，可证明 ts 单位为毫秒且指向开盘 |
| E5 | 机制归因错误 | 解释与数据对不上 | 对声称的机制单独做检验，例如声称动量就去测自相关；实测 -0.06 即证伪，真实机制是波动集聚 0.372 |
| E6 | 伪保护机制 | 单看门控更差，组合起来才好 | 逐个部件单独消融，不能只看组合结果 |

### 4.4 压力窗口

固定一组历史压力窗，每个策略变体都报这些窗口的表现，不允许只报全样本。
窗口按场所分别定义，具体日期在使用前须按 S4 或 S5 核实，不得凭记忆写死：

| 场所 | 压力窗类型 | 说明 |
|---|---|---|
| OKX（加密） | 大幅单日下跌与强平级联；交易所或稳定币信用事件；流动性枯竭时段（周末、亚洲凌晨）；资金费率极值期 | 至少覆盖一次全市场级去杠杆与一次单币种闪崩 |
| Trading 212（英股） | 大盘急跌与波动率骤升期；个股财报跳空；英国宏观事件日（利率决议、财政声明）；假期前后低流动性日 | 至少覆盖一次系统性回撤与一次个股跳空 |

窗口清单一经在预注册中冻结，后续各轮沿用同一组，不得逐轮挑选对结论有利的窗口。

## 五、阶段 4：裁定与设计定稿

### 5.1 交叉筛选

按 `screening_criteria.md` 逐族打分，产出 `screening_matrix.md`；
逐条回答阶段 1 写下的怀疑点，回答形式为「证实 / 证伪 / 无法判定」加依据。

### 5.2 参数预注册

入选策略的每个参数（阈值、窗口、仓位上限、冷却期）在 `4_strategy_design/` 中写定
并注明来源：来自文献、来自实证、还是人工设定。人工设定的参数必须做敏感性检验
并在报告中标注。

### 5.3 敏感性检验

对每个关键参数做单变量扫描，报告结果对参数的敏感程度。
若某参数微调即翻转结论，该策略判为不可用。

## 六、阶段 5：对抗性证伪

对定稿策略组织 10 至 15 个攻击向量，每个都要给出具体反驳或承认，
不允许「风险已识别」式的无实质回应。

标准攻击清单（按项目调整增删）：

| # | 攻击向量 |
|---|---|
| 1 | 回测数据是合成或近似的，不是真实成交价 |
| 2 | 全样本收益由某个特殊年代支撑，当下不可复制 |
| 3 | 参数过拟合 |
| 4 | 某个保护机制是伪保护，单独使用反而更差 |
| 5 | 历史最恶劣场景升级重演 |
| 6 | 单日跳空击穿风控地板 |
| 7 | 信用风险：曲线回测里没有违约事件 |
| 8 | 资金端可得性（正回购权限、跨季尖峰） |
| 9 | 锚定关系漂移（央行干预、制度变更） |
| 10 | 与既有策略抢通道、保证金或额度 |
| 11 | 容量与策略衰减 |
| 12 | 前视偏差（代码级核查） |
| 13 | 执行时点与成交假设，例如信号日收盘成交是否构成前视 |
| 14 | 交易成本与冲击成本压力测算，给出超额归零的成本临界点 |

每条攻击的处理写成四段：攻击描述、检验方式、结果、裁定（承认并给缓释手段，
或反驳并给证据）。总裁定放在文末。

## 七、阶段 6：循环（新方向、验证、裁定）

这是本流程与一次性研究的关键差别：每一轮新探索都必须走完整个子循环。

### 7.1 写预注册文档

位置为 `5_adversarial/round<N>_prereg.md` 或 `6_<topic>/prereg.md`，四块内容：

1. 先验立场：动手前写下预期结果。例如频域分析预先写明「收益率变动序列预期为
   近白噪声、无显著峰；若确实无峰，这是负面但有价值的结果」。
   有了这一句，负面结果就不会被事后包装成失败。
2. 判定标准：一个「发现」要成立须同时满足哪几条，包括统计显著性检验及其多重比较校正、
   分半样本稳定性、时域交叉验证、能翻译成可执行规则。分级：全部满足为成立；
   部分满足则如实记为对应等级。
3. 实验清单：逐项列出，含预期结果。
4. 采纳规则：新部件要进策略须同时满足的硬条件，例如：

   | 规则 | 内容 |
   |---|---|
   | R1 | 全样本 Calmar 优于对应基线 |
   | R2 | 近三年年化不低于基线 |
   | R3 | 任一压力窗回撤不比基线恶化超过 0.10pp |
   | R4 | 机制可用一句话讲清收益来源，且不与既有策略同源 |
   | R5 | 网格择优出来的参数点，须在多数年代子样本中同样优于基线 |

   预注册时即写明「预期大部分实验会失败，失败结果同样入档」。

### 7.2 跑实验与 7.3 写裁定文档

逐项对照采纳规则，输出采纳、否决或降格为备选，并说明否决理由。
裁定文档与预注册文档成对存在。

### 7.4 循环终止条件

以下任一满足即停止本轮循环，进入写报告：验收标准全部达成；
或连续两轮探索无新部件被采纳（方向已枯竭，如实写入报告）；
或用户给出新的约束需要重新立项。

### 7.5 外部验证（有官方基准可比时必做）

用独立的官方指数或公开数据比对本研究的合成回测，标准同样预注册。示例：

| # | 预注册标准 |
|---|---|
| 1 | 月度收益相关性不低于 0.7 |
| 2 | 年化收益差不超过 0.8pp，且方向符合先验（合成口径应偏保守还是偏乐观，先写定） |
| 3 | 关键压力窗回撤同量级，容差 ±0.3pp |

不通过则合成回测可信度降级，报告结论相应加不确定性标注，不是删掉不提。

## 八、阶段 7：写报告

### 8.1 主交付：md 报告

骨架：

```
1. 立项背景与目标（含验收标准逐条）
2. 研究方法（预注册链条、数据口径、局限）
3. 候选筛选结论（矩阵与淘汰理由）
4. 入选策略完整逻辑
   4.1 架构总览
   4.2 收益来源（逐个，并论证互不重叠、与既有策略正交）
   4.3 实证结果（全样本、分年代、全部压力窗）
   4.4 前瞻收益预算（当前市场口径，如实呈报缺口）
   4.5 回撤控制属结构保证还是历史统计（区分清楚）
   4.6 主要风险与缓释手段
   4.7 与既有策略的相关性
5. 执行与上线（含上线前必核清单）
5A/5B/5C. 各轮增补（每轮循环一节，含负面结果）
6. 局限性声明
7. Reference 清单（关键决策对应具体来源）
```

### 8.2 文体

按 `AGENTS.md` §2.1.2：技术 md 面向机器读者，无 emoji、无装饰符号、无渲染性修辞、
不用箭头链替代因果陈述，采用编号章节加表格加平实技术陈述。
按 §2.2：对外留痕口径，无第二人称、无交互过程引用、无 AI 署名。
按 §2.3：报告正文中文，脚本与代码注释美式英文。

### 8.3 Reference 清单（强制）

每个技术结论、数值、口径判断追溯到具体来源；禁止「根据文档」「根据代码」这类
不指名表述；没有来源的决策显式标注未证实。

### 8.4 可选交付（按用户要求增加）

| 形式 | 用途 | 要点 |
|---|---|---|
| HTML 总报告 | 供他人阅读的汇总件 | 自包含单文件、图表 base64 内嵌；公式与直觉简述，不放证明；中立第三人称 |
| PDF | 归档或打印 | 由 HTML 经 headless Chrome 重渲染，同名同目录 |
| LaTeX 理论汇编 | 教科书式推导留档 | 每条定理配 intuition 与出处；负面结果与限制单列一章 |

不在本流程内：把成果并入策略矩阵汇总件（例如 `reports/strategy_matrix.html`）。
那是独立的合并任务，需另行确认格式与备份要求。

## 十、与回测层的衔接（硬性）

凡研究涉及回测或样本外评估，动手前必须先读 `/backtest-discipline`，逐条采用其
数据口径、切分、指标、检验与审计三件套，以保证轮与轮之间方法一致、结果可比。

1. 与该 skill 的任何偏离：(a) 在该轮预注册中单列「协议偏离清单」逐条写明；
   (b) 在交互回复中显式提示使用者本轮回测方法与协议存在偏离，需人工核验。
   未经使用者确认，不得以偏离口径出主结论。
2. 研究层的方向性筛选可用轻量口径（不含滑点与费率的信号收益）快速排除，
   但任何要进入实盘候选的结论必须走成本级回测，含真实费率档、滑点、
   最小下单量取整、限频约束，并按 `/backtest-discipline` §五 出率指标。
3. 两个场所（OKX 与 Trading 212）的研究结论分开预注册、分开裁定，
   不得把一边的阈值、费率假设、时段假设套到另一边。
