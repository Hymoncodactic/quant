# 无未来函数三件套的落地设计

依据：`/backtest-discipline` §一。三件套任一缺失，该轮回测判无效。

## 1. cutoff 断言（在线检查，非事后目视）

1. 结构性保证：`BarFeed` 按时间游标推进，策略回调收到的市场视图对象
   （MarketView）只持有 ts ≤ t 的 bar。视图不暴露完整 DataFrame，
   只暴露截止游标的切片访问器。
2. 四项守卫的落地形态（全程开启，不设关闭开关）：
   - **步守卫（运行时断言）**：`fill.step > order.submitted_step`，禁止同 bar
     成交（`/backtest-discipline` §二.1）。
   - **时间守卫（运行时断言，日内）**：`fill.ts >= order.submitted_ts +
     interval`——决策用到提交键所在 bar 的收盘，该信息在 ts + interval 才
     存在；混交易所时间轴相邻步可小于一个 interval，步守卫覆盖不了此情形。
     撮合资格同理按时间（订单 eligible_ts = 提交键 + 整数个 interval）。
   - **视图 cutoff（结构性保证）**：BarFeed 游标只追加已递送的 bar，
     MarketView 只引用该历史，`bar.ts <= t` 由构造成立，无旁路写入口。
   - **FX 可得性（结构性保证 + 越界抛错）**：FxSeries 只返回
     `bar.ts + interval <= 查询时刻` 的收盘，查询早于首个可得值时抛异常
     而非外推。
3. 断言失败抛异常终止整轮回测，不降级为警告。

## 2. 故意前视对照（工具臂）

1. 引擎提供 `lookahead_probe` 开关（默认关闭，仅供检验，结果文件强制带
   `PROBE` 标记，禁止进入任何报告主表）：开启后策略视图额外包含 t+1 根 bar。
2. 判定逻辑（两条都要）：
   - 干净实现下，开启前视后收益应显著上升，证明该检验有判别力；
   - 若开启前视与关闭结果几乎相同，说明检验无效（或策略未用到价格信息），
     换检验方式。
3. 落地为可执行脚本（`scripts/` 下，日期前缀），不做人工目视。
   合成数据基准：构造「用 t+1 收益作信号」的探针策略——正确引擎下它只能在
   t+1 开盘成交、信号与可实现收益错开一根 bar；引擎若泄漏未来，
   其收益将系统性为正且远超噪声。

## 3. 特征可测性逐项论证

策略接入回测前，逐特征填写下表并存入该策略的预注册文件
（`research/prereg/`，`/backtest-discipline` §四.1）：

| 特征 | T 时刻取值用到的数据 | 最晚数据时间戳 | 可测性论证 |
|---|---|---|---|

引擎侧的配套约束：

1. 标准化/分位数等统计量只允许用滚动窗或扩展窗（截止 t），
   禁止全样本统计量进入信号路径。
2. 日线模式下,t 交易日收盘价属于 t 时刻结束才可得：以 t 收盘生成的信号,
   最早在 t+1 开盘成交。引擎的调用顺序固定为
   「先结算 t 的成交 → 再以含 t 的视图调策略 → 订单排入 t+1」。
