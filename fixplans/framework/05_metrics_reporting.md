# 绩效口径与结果落地计划

依据：`/backtest-discipline` §五（业绩率口径）、§八（单一权威口径）、§九（产出义务）、
`CLAUDE.md` §2.6（收益一律用率呈现）。

## 1. 本金口径

1. 本金 = 回测期内**最大同时占用资金**（GBP 口径，含在途订单冻结额）。
   逐时刻占用序列由账本显式给出，本金取其峰值。
2. 同时报告：单笔占用最大值、单笔占用均值。峰值等于单笔最大值时写明
   「持仓从未重叠」。
3. 引擎不接受「计划额度」作为本金输入；率指标一律除以实测峰值占用。

## 2. 年化与比率

| 指标 | 口径 |
|---|---|
| 年化收益率 | 总收益 ÷ 在线交易日数 × 年化因子 ÷ 本金；简单缩放不复利 |
| 年化因子 | t212 = 252（股票）。因子由场所适配层提供，引擎不内置默认值，避免跨场所误用（`/backtest-discipline` §十） |
| 在线交易日 | 策略在场日期并集，无成交日按 0 收益计入 |
| 夏普 | 日收益率均值 ÷ 标准差 × √年化因子；日收益率序列**只取在线交易日**（occupied > 0 的日），与年化收益共用同一日基底；无风险利率取 0，取非 0 须在结果元数据写明 |
| 最大回撤 | 权益曲线峰谷差，报 GBP 值与占本金比两个数 |
| 换手率 | 口径裁定：**双边、含费用**——各成交的 GBP 现金流绝对值合计 ÷ 本金（一买一卖的往返约计入两倍市值）；指标键名 `turnover_both_legs_on_capital` 显式标注该口径 |
| 其余必报 | 卡玛、盈亏比、平均盈亏比、胜率 |
| 中位数类 | 带符号中位与绝对偏离中位**分别列出**（`CLAUDE.md` §2.3） |

全部标注为样本内区间统计量。β 分解（对基准回归、Newey-West 标准误）
属策略评估阶段产物，引擎只负责输出日收益率序列供其计算。

## 3. 单一权威口径机制

1. 每轮回测运行时必须显式声明 `arm` 标签与完整口径参数
   （成本档、滑点、冷却、故障开关、数据窗口、策略版本）。
2. 权威口径 = 保守口径全开 + 最坏费率档 + 全部故障开关按缺陷目录默认值开启。
   对照口径（如无故障理想执行）单独落文件，文件名带 `ideal` 标记。
3. 结果文件自含全部口径参数（元数据 JSON），报告层只从结果文件派生数字，
   不重算实验。

## 4. 结果文件

1. 目录 `backtest/results/`（gitignore，`common/paths.py::DIR_BACKTEST_RESULTS`）。
2. 每轮落三件：
   - `<run>.trades.parquet`：逐笔成交（提交时刻、成交时刻、方向、数量、
     成交价、各成本项分列、订单终态）。
   - `<run>.equity.parquet`：逐时刻权益、现金（分币种）、占用资金。
   - `<run>.meta.json`：完整配置、口径参数、数据窗口、数据缺口表、
     统计指标、代码版本（git commit）。
3. `<run>` 命名：`<strategy>_v<M>_<m>_<p>_<arm>_<window>_<参数摘要>`，
   全 ASCII，参数进文件名（`/quant-code-standards` §4.5.1）。
4. 落盘经 `common/store.py::write_table`（原子写入）。

## 5. 跨块一致性断言

报告或汇总前执行：同一 run 的 trades 笔数与金额合计 == equity 曲线推进所用
成交记录 == meta.json 内统计指标的输入笔数。任一不等即停
（`/backtest-discipline` §八.3）。
