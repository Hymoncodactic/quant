# A0 时区加固计划（DST 错配窗口防御）

状态：待办。本计划源自 2026-08-29 的 DST 时序专项审计。审计裁定：现行代码在
伦敦/纽约夏令时错配窗口（2026-03-08..03-29、2026-10-25..11-01 及历年同构窗口）
内全部正确，实证覆盖决策键推导、FX 钉制（decision_key − 90 分钟）、会话门控、
日线本地日对齐与回测成交时序。以下两项为防御性加固：当前不可达或不触发，
但其正确性依赖未受代码保护的外部前提，前提一旦失效即为静默错位。

## 1. decision_key 改为墙钟构造

- 文件与函数：`trading212/execution/instruments.py::decision_key()`
- 现状：`pd.Timestamp(session.date_ny, tz="America/New_York") + Timedelta(15h30m)`。
  pandas 对 tz-aware 时间戳加 Timedelta 是绝对时间加法，在 DST 切换日会偏出
  墙钟一小时（实证：2026-03-08 得 16:30、2026-11-01 得 14:30）。
- 不可达前提：美股 DST 切换固定在周日，无交易会话（AAPL 全部 11,520 个日线
  会话中周日为 0）。该前提是交易所行为，不受本仓库控制。
- 改法：改为墙钟构造
  `pd.Timestamp(f"{session.date_ny} {DECISION_TIME_NY}").tz_localize(EXCHANGE_TZ)`，
  使切换日也得到正确的 15:30 本地时刻。
- 验收：新增单测断言 2026-03-08 与 2026-11-01（假想会话日）的 decision_key
  的纽约墙钟均为 15:30；既有 19:30Z(EDT)/20:30Z(EST) 断言保持不变。

## 2. daily_rows 拒绝 FX 符号

- 文件与函数：`trading212/execution/market_data.py::daily_rows()`
- 现状：对一切传入符号按纽约本地日贴日期标签。FX 日线（GBPUSD=X）戳在伦敦
  午夜（GMT 期 00:00Z、BST 期前一 UTC 日 23:00Z），转纽约后两个制式下都落到
  前一天——若被传入，标签整年错一天。
- 不触发前提：当前唯一调用点 `session_cycle.py` 只传 trade_symbols 与
  state_symbol，FX 不在内；回测侧同口径。该前提只由调用纪律维持。
- 改法（二选一，推荐前者）：
  (a) 函数开头加拒绝断言：传入 FX 符号（`=X` 后缀）即 raise ValueError；
  (b) 按 `_exchange_tz(symbol)` 转交易所本地日再贴标。
- 验收：新增单测断言传入 `GBPUSD=X` 时 raise（方案 a），或断言 BST 期 FX 日线
  行的标签等于伦敦本地日（方案 b）。

## 3. 不改动项（记录裁定依据）

| 项 | 裁定 | 依据 |

| 日线对齐 | 保持 | trading_key 按交易所本地日归位 23:00Z 前日戳；UTC 日期连接的反例（BST 期每周五掉杆）实测存在但代码未采用 |
| 回测成交时序 | 保持 | 301 笔真实回测成交 0 笔早于提交，289 笔 at_close 全部为纽约墙钟 15:30（两制式各自成立） |
| 看板"最近更新"标签恒用浏览器本地时区 | 保持 | 纯展示口径，不进任何交易决策 |
