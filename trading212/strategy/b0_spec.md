## 1. 一段话说清策略

每个交易日收盘前，先让 A0 说出它今天想持有哪些股票（受它的两道市场闸约束）。
A0 想持有的股票按 A0 的规则占用资金；账户里剩下的全部资金——A0 没开的槽位、
A0 闸关闭时的全部现金——都投进 A1 当期的 20 只名单，等权。两套名单重叠的股票
按 A1 的定量规则占用（可切换为按 A0）。这样账户每天都接近满仓，
把 A0 常态下约 45% 的闲置现金用起来。

## 2. 术语与记号

| 记号 | 含义 |
|---|---|
| `S0` | A0 当日的信号集：A0 模块给出目标股数 > 0 的股票（信号开且两闸开） |
| `B1` | A1 当期名单（20 只等权，每 21 个交易日重排一次） |
| `E` | 账户总权益（GBP）= 现金 + 全部持仓市值折英镑 |
| `active` | A0 的活跃集（18 只中有 ≥ 253 根日线者） |
| `priority` | 重叠股票的定量归属，`"a1"`（默认）或 `"a0"` |
| A0 名下 / A1 名下 | 一只股票当日按哪套规则定量 |

## 3. 规则（精确定义）

### 3.1 读取 A0 的信号集

A0 的模块按「它自己看得见的资金」定量：权益只累加现金与 18 只名单内的持仓。
在共用账户里，当 A1 持有了资金，A0 看到的权益接近零，会把想买的股票算成 0 股，
进而被误读为「不想要」，从此永远进不了场。因此 B0 **不把 A0 的股数当定量用**，
只取其信号集：把一个现金为 1,000,000 英镑、持仓为真实持仓的合成组合视图交给
A0 的 `compute_targets`，取目标股数 > 0 的股票为 `S0`。免加仓分支对已持有的股票
返回真实持仓量，仍 > 0，不受合成现金影响。

### 3.2 归属划分

```
if priority == "a1":
    a0_sized = S0 − B1          # 只有不在 A1 名单里的 A0 股票按 A0 定量
    a1_sized = B1               # A1 名单全部按 A1 定量（含与 A0 重叠者）
else:                           # priority == "a0"
    a0_sized = S0
    a1_sized = B1 − S0
```

### 3.3 A0 名下的定量（沿用 A0 规则，但用全账户权益）

```
slot   = E / |active| × 0.99
held   = 持仓 + 未成交挂单
target[s] = held if held > 0 else floor_0.0001(slot × fx / C[s, t])     # 免加仓
a0_value = Σ_{s ∈ a0_sized} target[s] × C[s, t] / fx
```

### 3.4 A1 名下的定量（吸收剩余资金）

```
C1  = E × 0.99 − a0_value                  # A0 之外的全部资金
per = C1 / |a1_sized|
tgt = floor_0.0001(per × fx / C[s, t]) if (per > 0 and C[s, t] > 0) else 0
held = 持仓 + 未成交挂单
target[s] = held if (held > 0 and tgt > 0 and |held − tgt| / tgt < 0.10) else tgt   # 10% 免动带
```

免动带的作用：A1 名下持仓每日重算目标，但只有偏离超过 10% 才下单，
避免价格漂移造成的日常换手；被拒的订单因每日重算而在次日自动重试。

**三种结果必须分开处理**（2026-09-03 修订；原文只写了前两种，把「行情延迟」
与「无价格」混为一谈）：

| 情形 | 判据 | 目标 | 理由 |
|---|---|---|---|
| 清零 | `C1 ≤ 0`（A0 占满 99% 权益），或该股**根本没有价格** | `tgt = 0`，免动带不生效，持仓全部卖出 | 原文规则，实现时不得省略 |
| 冻结 | 该股在 `injection["thin"]` 内（当日决策键无 bar），或排名表陈旧超过 3 个场次使整条 A1 腿 `a1_frozen` | 目标 = 当前持仓，不买不卖；其市值计入「已占用」后再算 `C1`，且**不计入** `\|a1_sized\|` 分母 | 无当日价格时无法定量；行情延迟不是「这只票不该持有」的证据，按缺价卖出会把一次数据故障变成一次实盘清仓 |
| 免动带 | 其余（`per > 0`、`close > 0`、`tgt > 0` 三者皆真） | 偏离 < 10% 保留，否则重定量 | 原文规则 |

三条守卫（`per > 0`、`close > 0`、`tgt > 0`）必须在比较 10% 带**之前**求值：
`tgt = 0` 时 `|held − tgt| / tgt` 是除零。

### 3.5 清零与守卫

1. 已持有但不在 `a0_sized ∪ a1_sized` 中的股票，目标为 0（全部卖出）。
2. 18 只 A0 名单中未被赋值者，目标为 0。
3. 非美股交易日（GBPUSD 在美股休市日仍有 bar）直接返回空目标，不决策。
4. FX 缺失时返回空目标。

### 3.6 A1 名单的来源

与 `a1_spec.md` 完全一致：宽池 12-1 动量、因果流动性准入、每 21 个交易日重排、
前 20 / 前 40 缓冲带、等权、无市场闸。B0 的回测中该名单由入口层按 A1 规格
预先生成为「重排日 → 名单」计划（验证窗内 80 次重排、涉及 223 只），策略闭包按日查表。

## 4. 完整决策伪代码（每个交易日收盘执行一次）

```
if today 非美股交易日: return {}
if today 是 A1 重排日: B1 = A1 今日名单
S0     = { s : A0.compute_targets(view, 合成现金视图(portfolio), a0_params)[s] > 0 }
active = [ s in 18 只 if len(bars[s]) >= 253 ]
E      = cash + Σ_{所有持仓} qty × close / fx
a0_sized, a1_sized = 按 §3.2
slot = E / len(active) × 0.99
for s in a0_sized: target[s] = held(s) if held(s) > 0 else floor(slot × fx / close[s])
a0_value = Σ_{a0_sized} target[s] × close[s] / fx
C1 = E × 0.99 − a0_value ;  per = C1 / len(a1_sized)
for s in a1_sized:
    tgt = floor(per × fx / close[s]) if (per > 0 and close[s] > 0) else 0
    target[s] = held(s) if (held(s) > 0 and tgt > 0 and |held(s) − tgt| / tgt < 0.10) else tgt
for s in 持仓 ∪ 挂单: if s not in target: target[s] = 0
for s in 18 只: target.setdefault(s, 0)
return target
```

## 5. 执行口径（已验证）

真实引擎，interval 1d，fill_timing `same_close`（`t` 日 bar 决策、`t` 日收盘成交，
含收盘临近滑移），最坏与实测两档费率，本金 £1,000，
窗口 2020-01-02 至 2026-08-28（1,673 个美股交易日）。A0 自 2010-01-04 预热、2020-01-02 起用；
A1 名单自 2020-01-02 起。

**拒单的构成与机制**（按各臂 trades 件 `order_reason` 统计）：

| 原因 | 最坏档（共 2,901） | 实测档（共 3,113） |
|---|---:|---:|
| 现金不足（买入力校验） | 2,075（A0 名下 384、A1 名下 1,679、其他 12） | 2,031（A0 名下 341、A1 名下 1,679） |
| 订单金额低于 £1 最小值 | 661 | 565 |
| 残量低于最小值 | — | 517 |
| 随机拒单（故障开关 F5） | 139 | 0 |
| 卖出未持有 | 26 | 0 |

要点：现金不足类拒单里约 82% 是 **A1 每日重定量的买单**，不是 A0 的买单；
两档数量相近说明主因是账户结构而非故障注入（最坏档另有 F9 买入力缓冲系数 0.95 抬高计数）。
机制并非「卖出款未到账」——`same_close` 下卖单在提交时刻即成交并入账
（`backtest/t212/broker_sim.py` → `same_close.py` → `ledger.apply_fill`）；
真正原因是**提交顺序**：参考实现先写入 A0 名下目标、再写入 A1 名下目标，引擎按字典
插入顺序逐笔提交，买单排在同日卖单之前，提交时刻现金尚未因卖出增加。
把卖单排在买单之前提交即可消除这类拒单，无需为 A0 预留现金缓冲（§9 契约第 6 条）。
£1 最小订单类拒单是 £1,000 本金下的小额重定量所致，本金放大后消失。

## 7. 解读与限定

1. **资金效率确实提高**（占用 55% → 96%），CAGR 高于两池平均 15.9 个百分点。
2. **但风险画像变成 A1 的**：回撤 44% 与 A1 独立几乎相同，因为 A0 退场时整池即 A1。
   两池合计因一半仓位是 A0，回撤压到 30.6%，Calmar 与 B0 持平（1.24 对 1.22）。
   打满换来的是更高的绝对收益，不是更好的风险调整收益。
3. **每日打满的代价**：换手 14.4 腿/年（A1 独立 4.9），拒单约 2,900–3,100 笔（§5，
   主要是 A1 每日重定量与 £1 最小订单，参考实现的提交顺序可优化）。
4. 与 B0 高度相关的是 A1（0.91），B0 的表现由 A1 主导。
5. 两套名单都是 2026 年的存活者名单，绝对收益偏高；三条曲线共享该偏差。
6. 验证窗是 A1 的验证段（A1 在 2012–2019 选出），A0 在此窗内非样本外；窗口为牛市窗。
7. 未做过 `priority == "a0"` 的回测；未做 A0 现金缓冲变体；未按 A1 采纳标准裁定。
8. £1,000 下单仓约 £25–55，0.0001 股步进不构成约束（A0 £1,000 与 £10,000 结果在四位
   有效数字内成比例，期末差 £1.93）；但 £1 最小订单在小额重定量时会触发拒单（§5）。

## 9. 未来模块的契约（实现 `b0_v0_0_1.py` 时须遵守）

1. `STRATEGY_NAME = "b0"`、`STRATEGY_VERSION = "0.0.1"`，公开面
   `compute_targets(view, portfolio, params)`，纯函数。
2. 依赖注入（2026-09-03 修订，与 `fixplans/t212/b0/00_coordination.md` §2.3 对齐）。
   原文说「注入重排日 → 名单计划」，那是回测入口的形态；实盘不可能预先知道未来的名单。
   实际契约是一个 dict，实盘与回测共用同一组键：

   | 键 | 含义 |
   |---|---|
   | `a0_mode` | `"rows"`（实盘）或 `"view"`（回测），决定 A0 的活跃集与日线视图从哪来 |
   | `a0_rows` | 实盘专用：symbol → `[(iso_date, o, h, l, c), ...]`，A0 的日线历史 |
   | `a1_rank` / `panel` | 二者互斥。实盘给盘前算好的排名表，回测给 closes/volumes 两张面板 |
   | `rank_as_of` | 排名表对应的场次；模块断言其不晚于决策日 |
   | `rank_stale_sessions`、`a1_frozen` | 陈旧程度与冻结标志（§3.4 的「冻结」一行） |
   | `a1_book` | 上一次重排的名单，取自 `a1_plan` 记录流，**不从持仓推导** |
   | `sessions` | 自重排锚点起的美股场次序列（真值为本地 SPY 日线，半日市计入） |
   | `thin` | 当日无决策键 bar 的名字，按 §3.4 冻结 |

   A1 的名单由 B0 内部调 `a1_v0_0_1.make_strategy(injection)` 得出，不再由入口层预生成。
3. 参数（`trading212/config/strategies/b0_v0_0_1.yaml`）：

| 键 | 值 | 出处 |
|---|---|---|
| `priority` | "a1" | §3.2 |
| `a1_band` | 0.10 | §3.4 |
| `slot_headroom` | 0.99 | §3.3、§3.4 |

| `a0_params` | 引用 `a0_v0_0_1.yaml`，但 **`live_from` 覆盖为 B0 的起用日**（参考实现为 "2020-01-02"；yaml 原值 "2018-01-01" 会让 A0 在起用日之前就在合并账户内交易，§9.4 的期末数将不可复现） | §3.1、§5 |
| `a1_params` | 引用 `a1_spec.md` §13 参数表 | §3.6 |

4. 复现判据（2026-09-03 修订）。原文的 £17,469.48 / £18,793.70 **不可达，且对任何实现都不可达**：
   参考实现 `make_merged` 按集合迭代写入目标，引擎按插入顺序提交，故结果随
   `PYTHONHASHSEED` 变（同源问题在 A1 臂实测两个种子相差 £1,626）；且日线复权是回溯的，
   隔日的数据湖不复现前一日的成交价。该脚本已于 2026-09-03 改为 `sorted()` 迭代，确定化。

   改判据为**等价性**：`scripts/20260903_b0_module_backtest.py` 在同一进程、同一面板上
   同时跑模块臂与参考臂，期末权益逐位相等。2026-09-03 实测（1,673 场次、£1,000、
   引擎起 2010-01-04、`sells_first = false`）：

   | 档 | 模块 | 参考 | 差额 | 成交 | 拒单 |
   |---|---:|---:|---:|---:|---:|
   | worst | £16,797.888979 | £16,797.888979 | £0.000000 | 6,360 | 3,410 |
   | actual | £18,517.784162 | £18,517.784162 | £0.000000 | 6,423 | 3,465 |

   结果件 `backtest/results/b0_module_vs_reference_20260903.csv`。
5. 参考实现：`scripts/20260902_a0_a1_merge_backtest.py::make_merged`（含 `_SignalView`）。
6. 提交顺序（2026-09-03 实测，原列为「已知可改进项」）。把同日卖单排在买单之前
   （参数 `sells_first = true`，实盘默认）确实大幅减少拒单，但在本窗口上**降低**期末权益：

   | 顺序 | 期末（worst） | 拒单（worst） | 期末（actual） | 拒单（actual） |
   |---|---:|---:|---:|---:|
   | 先 A0 后 A1（参考实现） | £16,797.888979 | 3,410 | £18,517.784162 | 3,465 |
   | 先卖后买（实盘默认） | £15,663.665102 | 1,640 | £16,231.623374 | 458 |

   worst 档拒单减少 52%、期末低 6.7%；actual 档拒单减少 87%、期末低 12.3%。
   换手同向上升（14.4 → 16.6 腿/年 worst，14.7 → 18.6 actual）。机制：被拒的买单等于没有换手，在本窗口上省下的
   成本多于错过的收益（最坏档每腿换汇 15 bp）。因此「拒单少」不等于「更好」。
   实盘仍取 `sells_first = true`，理由不是收益而是**可解释性**：买单在前时，
   实际成交的账本取决于场所的现金入账时点而非策略的目标，这种漂移回测建模不了
   （回测里被拒是干净的一次不成交，实盘里是部分成交加次日以另一价格重试）。
   该取舍属口径选择，可由用户改回 false。
