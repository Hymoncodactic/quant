## 1. 一段话说清策略

在约 1,500 只美国大中小盘股票（S&P 1500 且 Trading 212 可交易）里，每 21 个交易日
做一次筛选：先剔除流动性不足的，再按「过去 12 个月、跳过最近 1 个月」的价格涨幅排名，
取前 20 只等权持有。已持有的股票只要还排在前 40 名就不卖（缓冲带），空出的名额从
前 20 名里未持有者补入。不设任何市场级开关：不看大盘趋势、不看波动率、不止损。
两次重排之间不做任何交易，持仓随价格自然漂移。

## 2. 术语与记号

| 记号 | 含义 |
|---|---|
| 交易日 / 场次 | 美股一个交易日（以 SPY 的日线是否存在为准） |
| `t` | 决策日（某个交易日的收盘） |
| `C[s, t]` | 股票 `s` 在交易日 `t` 的收盘价（Yahoo 日线，已按分红与拆股回溯复权） |
| `V[s, t]` | 股票 `s` 在交易日 `t` 的成交量（股数） |
| `t − k` | 交易日 `t` 往前数第 `k` 个**交易日**（按面板的行索引偏移，不是日历日） |
| 面板 | 行 = 交易日、列 = 股票的二维表；某股票某日无数据即为 NaN |
| N | 目标持仓数，20 |
| 2N | 缓冲带宽度，40 |
| book | 上一次重排后的目标名单（含权重） |

### 3.2 因果流动性准入（每个决策日重算）

股票 `s` 在决策日 `t` 可入选，当且仅当以下四条全部成立，且只用 `t` 及以前的数据：

| # | 条件 | 定义 | 阈值 |
|---|---|---|---|
| E1 | 成交额 | `median(C[s, t−251..t] × V[s, t−251..t])`，滚动 252 个交易日的日成交额中位数 | ≥ 1,000,000 USD |
| E2 | 零成交量占比 | `1 − mean(V[s, τ] > 0 且 C[s, τ] 非 NaN, τ ∈ t−251..t)` | < 1% |
| E3 | 历史长度 | 截至 `t` 有收盘价的交易日累计数 | ≥ 300 |
| E4 | 参与率 | `640 / E1 的中位成交额`（640 USD ≈ 单腿 500 英镑，本金 10,000 英镑分 20 份，汇率 1.28） | < 0.1%（被 E1 蕴含） |
| E5 | 已验证 ticker | 该标的在 `data/reference/t212_universe_ticker_map_<date>.json` 中有非空 `ticker` | 必须有（**实盘专属**） |

**E5 只在实盘臂生效**（参数 `require_verified_ticker`，研究臂置 false）。
理由是执行侧的硬约束而非研究判断：`trading212/execution/instruments.py::order_ticker`
对未映射标的抛 `KeyError`，一只未映射的候选一旦进入名单，整个决策会在下单时崩掉。
映射由 `scripts/20260903_build_universe_ticker_map.py` 逐个对场所元数据求证。
**匹配顺序是 `shortName` 优先，`<SYMBOL>_US_EQ` 前缀只作兜底**，两者都要求
`STOCK` 且 `USD`。顺序反过来会买错公司：Trading 212 在公司改名后**保留原 ticker id**，
把光杆 symbol id 给了现在持有该 symbol 的那家。2026-08-21 元数据实测——

| 场所 ticker | shortName | 公司 |
|---|---|---|
| `CNX_US_EQ` | CNR | Core Natural Resources |
| `CNX1_US_EQ` | CNX | CNX Resources |
| `CR_US_EQ` | CXT | Crane NXT |
| `RBC_US_EQ` | RRX | Regal Rexnord |
| `UA_US_EQ` | UAA | Under Armour A 类 |
| `GEN_US_EQ` | GENNQ | Genesis Healthcare |

前缀优先的旧规则把池内 CNX 映到 `CNX_US_EQ`（Core Natural Resources，另一家公司），
且池内 CNR 也映到同一条，五只标的映错、四个场所 ticker 被两个池标的同时占用。
2026-09-03 独立审查查出，已改为 shortName 优先并加三道拒绝闸：
前缀命中但其 `shortName` 是另一个池成员时拒绝、一符多配时拒绝、
一个场所 ticker 被两个池标的占用时**双方都拒绝**。
双重挂牌（同一 shortName 同时有美国线与伦敦线，如 DAR、FIVE）取唯一的 `_US_EQ` 线。

改后实测 1,501 条全部匹配（shortName 1,483、A0 手工核验 18），无歧义、无未匹配、
无重复占用。多候选与未匹配者 `ticker` 记 null，经 E5 自然不准入。

滚动窗口不足 252 个交易日时视为不满足。
实现：`research/xsmom_wide/run_study.py::eligibility`（L95–112）。
在选择段首个决策日（2012-01-03）满足准入的股票为 973 只；验证段首个决策日（2020-01-02）为 1,314 只。

**为什么必须是因果的**：本策略第一版曾用全样本（2010–2026）的成交额中位数做准入。
对抗复审证明这会以「未来成交额增长」为条件挑股票，且偏差不是配置中性的——
它把最优配置从「带缓冲带」翻成了「不带缓冲带」。任何复现都不得用全样本统计做准入。

## 4. 信号：12-1 横截面动量

对每只准入股票，在决策日 `t` 计算

```
score[s, t] = C[s, t − 21] / C[s, t − 252] − 1
```

即「从 12 个月前到 1 个月前的累计涨幅」。跳过最近 21 个交易日是动量文献的标准做法
（Jegadeesh & Titman 1993），目的是避开一个月内的短期反转。
`C[s, t−21]` 或 `C[s, t−252]` 任一为 NaN 时该股票本次无分数、不参与排名。

分数只用于**排序**，分数的大小不影响权重。
实现：`run_study.py::momentum_scores`（L174–177）。窗口 252 与 21 不做搜索（固定值）。

## 5. 重排日历

| 项 | 规则 |
|---|---|
| 频率 | 每 21 个交易日一次 |
| 计数 | 从策略启动日算起，启动日为第一个重排日；此后每逢「自上次重排起已过 21 个交易日」的收盘再重排 |
| 半日市 | 视为普通交易日计数 |
| 非重排日 | **不下任何订单**；不因价格漂移而调仓；不因个股跌出名单而卖出 |

回测中的启动日：选择段 2012-01-02、验证段 2020-01-02（两段各自独立计数）。

## 6. 选股：排名 + 缓冲带

设 `ranked` 为准入且有分数的股票按 `score` 降序排列的列表。

```
if book 为空（首次重排）:
    pick = ranked[:N]
else:
    keep  = [s for s in book.keys() if s in ranked[:2N]]      # 仍在前 40 名的老持仓，保持 book 中的顺序
    fresh = [s for s in ranked if s not in keep]              # 其余按分数降序
    pick  = keep + fresh[:max(0, N − len(keep))]
```

语义：

1. 老持仓只要还在**前 2N = 40 名**就保留；跌出 40 名才卖出。
2. 空缺名额从当前排名最高、且不在保留集中的股票依次补入。
3. `len(pick)` 通常等于 N；准入股票不足时可小于 N。
4. 缓冲带的作用是降低换手：无缓冲带时双边换手约 8.7 腿/年，有缓冲带约 5.5 腿/年，
   且选择段 Calmar 更高（0.88 对 0.71）。

实现：`run_study.py::run_config` L265–268。

## 7. 权重与定量

### 7.1 权重

等权：`w[s] = 1 / len(pick)`，对 `pick` 中每只股票。

明确**不采用**逆波动率（风险平价）权重：在 16 配置族的 8 个成对比较里，等权在 7 对中
优于逆波动率（唯一例外 N20|band+|gate+，该对逆波动率的选择段 Calmar 更高）；
机制上动量效应在低波动股票上更弱，与逆波动率权重相互抵消。

### 7.2 目标股数

在重排日收盘，对 `pick` 中每只股票：

```
equity_gbp = 现金(GBP) + Σ 持仓股数 × 当日收盘价(USD) / GBPUSD
shares[s]  = floor_to_0.0001( equity_gbp × w[s] × 0.99 × GBPUSD / C[s, t] )
```

| 常数 | 值 | 依据 |
|---|---|---|
| 余量系数 | 0.99 | 与 A0 相同（`trading212/config/strategies/a0_v0_0_1.yaml` L18 `slot_headroom`），为费用与价格滑移留 1% |
| 股数步进 | 0.0001 股 | Trading 212 碎股精度（`trading212/strategy/a0_v0_0_1.py` L100 `_SHARE_STEP`） |
| GBPUSD | 决策时刻可得的最新汇率 | 账户为英镑，标的为美元 |

不在 `pick` 中但当前持有的股票：目标股数为 0（全部卖出）。

| 波动目标 / 杠杆缩放 | 不做 |
| 行业约束 | 不做 |

| 非重排日调仓 | 不做 |

## 9. 完整决策伪代码（每个交易日收盘执行一次）

```
输入：
  closes  : 面板 C[s, t]，t 及以前的所有交易日，全部候选池股票，已复权
  volumes : 面板 V[s, t]，同上
  fx      : 决策时刻的 GBPUSD
  portfolio : 当前现金(GBP)与各股票持仓股数
  state   : {book: dict[s -> w], sessions_since_rebalance: int}

每个交易日 t 收盘：
  # 重排日历：自启动日起按交易日序号 i 计数，i % 21 == 0 为重排日（启动日 i = 0）
  if state.book 非空 and state.session_index % 21 != 0:
      state.session_index += 1
      return {}                                   # 非重排日：不下单
  state.session_index += 1

  # 准入（§3.2）
  eligible = {s : E1(s,t) and E2(s,t) and E3(s,t) and E4(s,t)}

  # 信号（§4）
  score = {s : C[s,t-21] / C[s,t-252] - 1  for s in eligible if 两个价格都非 NaN}
  ranked = 按 score 降序的 s 列表

  # 选股（§6）
  if state.book 为空: pick = ranked[:20]
  else:
      keep  = [s for s in state.book if s in ranked[:40]]
      fresh = [s for s in ranked if s not in keep]
      pick  = keep + fresh[:max(0, 20 - len(keep))]

  # 权重与定量（§7）
  w = {s : 1/len(pick) for s in pick}
  equity = portfolio.cash + Σ portfolio.shares[s] * C[s,t] / fx
  targets = {s : 0 for s in portfolio.shares if portfolio.shares[s] > 0}
  for s in pick:
      targets[s] = floor_0.0001( equity * w[s] * 0.99 * fx / C[s,t] )
  state.book = w
  return targets                                  # 执行层据此与现持仓做差下单
```

## 11. 风险与限定（必读）

1. **回撤是这个策略的本质，不是缺陷**。最大回撤 44.65% 发生在 2020 年 3 月崩盘，
   策略无任何保护机制，满仓吃完。最差单月 −23.3% 发生在 2026 年 7 月。
   动量策略的「动量崩溃」（急跌后急涨时组合正好持有跌得最狠的股票）是文献
   反复记录的现象。接受该风险是使用本策略的前提。
2. **存活者偏差**。候选池是 2026 年的成分名单，回测在 2012 年起就「知道」哪些
   公司活到了 2026 年。年化 43.77% 是被抬高的数字；A0 的 26.94% 同样被抬高。
   两者的相对比较共享该偏差，比绝对数字可信，但不干净。
3. **验证窗是牛市窗**（2020–2026）。
4. **对 A0 的收益优势未获统计认证**（t = 1.50）。
5. **费用口径**：最坏费率档下，真实引擎不重试被拒或延迟的订单（非重排日不下单），
   这使 A1 的回测被系统性低估，方向保守。
6. **数据**：Yahoo 日线；准入需要成交量；数据洞（如 2026-08-28 有 9 只标的缺日线）
   由「最近已知价估值、当日不可成交则冻结持仓」的规则处理。
7. **容量**：单腿约 500 英镑对准入门槛（日成交额 ≥ 100 万美元）的参与率 < 0.064%，
   本金 10,000 英镑量级无容量约束；至约 100 万英镑量级才开始受限。

## 13. 未来模块的契约（实现 `a1_v0_0_1.py` 时须遵守）

1. `STRATEGY_NAME = "a1"`、`STRATEGY_VERSION = "0.0.1"`，与文件名一致，
   否则 `backtest/engine/strategy_loader.py::load_strategy` 拒载。
2. 公开面 `compute_targets(view, portfolio, params) -> dict[str, Decimal]`：
   纯函数，不读网络、不写磁盘、不下单。
3. 引擎视图不能携带 1,500 只股票的历史，因此候选池的日线面板须由入口层
   经工厂函数注入（参照 `a0_intraday_v0_0_1.py::make_strategy(daily_history)` 的模式），
   并在模块内**按决策日严格切断**（断言注入数据的最大日期 ≤ 决策日）。
4. 参数（放 `trading212/config/strategies/a1_v0_0_1.yaml`，不写死在代码里）：

| 键 | 值 | 出处 |
|---|---|---|
| `n_hold` | 20 | §6 |
| `band_multiple` | 2 | §6 |
| `rebalance_every` | 21 | §5 |
| `mom_long` / `mom_skip` | 252 / 21 | §4 |
| `liq_window` | 252 | §3.2 |
| `min_dollar_volume_usd` | 1000000 | §3.2 E1 |
| `max_zero_volume_share` | 0.01 | §3.2 E2 |
| `min_history_bars` | 300 | §3.2 E3 |
| `order_usd_for_participation` | 640 | §3.2 E4 |
| `slot_headroom` | 0.99 | §7.2 |
| `universe_file` | `data/reference/b0_universe_1500_20260823.json` | §3.1 |
| `fx_symbol` | `GBPUSD=X` | §7.2 |

5. 重排计数状态不得藏在模块全局变量里；由入口层按重排日历传入「今天是否重排日」，
   或由模块从注入的交易日序列与启动日确定性推出。
6. 复现判据（2026-09-03 修订）。原文要求「期末权益与 §10.1 的 111,348 GBP 逐位一致」，
   该判据**不可达，且对任何实现都不可达**，两条实测理由：

   - 参考实现依赖进程哈希种子。`make_wide_strategy` 用集合推导写零目标，
     引擎按字典插入顺序提交，卖买交错随之改变，拒单构成随之改变。
     2026-09-03 同一份数据两个种子实测 £118,221.803491（seed 1）与
     £116,595.492465（seed 7）。该脚本已于同日改为按账本持仓顺序迭代，确定化。
   - 日线复权是回溯的。任一分红都会重写该标的整段历史，故某日记下的期末权益
     在次日用刷新过的数据湖不可复现。**选股是稳定的**：2026-09-03 重算的 80 次
     重排名单与 2026-09-02 记录的 `a0_a1_plan_a1_20260902.json` 逐次完全一致；
     不稳定的是成交价。

   改判据为**等价性**：`scripts/20260903_a1_module_backtest.py` 在同一进程、
   同一面板上同时跑模块臂与参考臂，两者期末权益必须逐位相等。
   2026-09-03 实测 1,673 个场次上两臂均为 **£132,653.185098**（worst 档、£10,000、
   引擎起 2019-06-03、1,784 笔成交、92 笔拒单），差额 £0.000000。
   该数字随数据湖变动，判据本身不随之变动。
