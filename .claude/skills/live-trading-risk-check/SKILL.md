# 实盘执行风险审查表

前置约束：

1. `CLAUDE.md` §3 资金红线是本表的上位约束。
2. 凡改动 `crypto_trading/execution/`、`trading212/execution/` 或任何风控闸，
   必须整表复查，不得只跑单元测试。

本表由团队 QMT 风险审查清单改写，检查项已按加密与英股两个场所重定。

---

## 一、检查表

逐条给出「通过」「缺失」「可疑」三种结论之一，并指出文件与行号。

### A 组：资金安全（CRITICAL，任一不过即禁止接实盘）

| # | 检查项 | 标准 |
|:--:|---|---|
| A1 | DRY_RUN 开关 | 存在且默认值为 True；所有下单与撤单路径都受其控制 |
| A2 | 实盘断言 | 提交订单前断言配置含 `live: true`，缺失即拒绝 |
| A3 | 密钥来源 | 只经 `common/secrets.py` 读取；代码、配置、日志中无明文 |
| A4 | 下单幂等 | 每笔带 client order id；重试前先查是否已存在 |
| A5 | 数量对齐 | 过 `align_order_size()`：向下取整到步进，且校验不小于最小下单量 |
| A6 | 价格对齐 | 过 `align_price()`：买向下、卖向上取整到 tick |
| A7 | 价格有效性 | 拒绝 `None`、不大于 0、偏离最新价超阈值的价格 |
| A8 | 提现权限 | 代码中不存在任何提现、划转、转账调用 |

### B 组：风控闸（HIGH）

| # | 检查项 | 标准 |
|:--:|---|---|
| B1 | 单笔金额上限 | `MAX_ORDER_NOTIONAL` 存在且生效 |
| B2 | 总仓位上限 | 按标的与账户两级设上限，超限拒单 |
| B3 | 日内笔数熔断 | `MAX_DAILY_ORDERS` 计数，跨日重置，防死循环刷单 |
| B4 | 日内亏损熔断 | 当日累计亏损达阈值即停止开新仓 |
| B5 | 止损 | 存在明确止损逻辑与触发后的强制平仓路径 |
| B6 | 杠杆（仅 OKX） | 显式设定并断言杠杆倍数；现货账户须断言非保证金模式 |
| B7 | 撤单重报状态机 | 撤单后有状态机防无限重报；重报次数有上限 |
| B8 | 冷却期 | 成交或失败后有最短间隔，防高频重复吃同一盘口 |

### C 组：状态一致性（HIGH）

| # | 检查项 | 标准 |
|:--:|---|---|
| C1 | 启动对账 | 进程启动后先拉柜台持仓与未成交委托，与本地状态比对 |
| C2 | 不一致处置 | 对账不一致时停止下新单并告警，不是自动修正 |
| C3 | 部分成交 | 部分成交回写本地持仓与剩余量，撤单后再核对 |
| C4 | 订单终态 | 终态集合定义明确；非终态订单有超时兜底处理 |
| C5 | 手工干预 | 能识别账户中非本策略产生的持仓与委托，不误当成自己的 |

### D 组：数据与信号（HIGH）

| # | 检查项 | 标准 |
|:--:|---|---|
| D1 | 行情新鲜度 | 下单前校验快照时间戳，过期即放弃本次信号 |
| D2 | 空数据守卫 | 计算指标前校验样本量下限；除法前检查分母 |
| D3 | 重复触发 | 同一根 bar 或同一信号不重复下单，去重键明确 |
| D4 | 时区与跨日 | 全链路 UTC；跨 UTC 零点、夏令时、交易所维护窗已处理 |
| D5 | 停牌与下架 | 标的停牌、退市、合约下架有识别与跳过逻辑 |

### E 组：运行与可观测（MEDIUM）

| # | 检查项 | 标准 |
|:--:|---|---|
| E1 | 关键日志 | 下单、成交、撤单、风控触发全部有日志，且带 `dry_run` 字段 |
| E2 | 异常包裹 | 网络与交易调用有 try-except，且区分可重试与不可重试 |
| E3 | 优雅退出 | 响应 SIGTERM，退出前撤销未成交委托并落地持仓快照 |
| E4 | 单例保护 | 防止同一策略被重复启动，用锁文件或端口占用实现 |
| E5 | 告警通道 | CRITICAL 级事件有触达用户的通道，不只写日志 |

## 二、输出格式

```
## 实盘风险审查报告

审查对象：<文件路径列表>
审查时间：<UTC>

### 通过 (N/31)
A1 DRY_RUN 开关 ：execution/router.py:18 `DRY_RUN = True`
...

### 未通过
- [CRITICAL] A5 数量对齐 ：execution/router.py:96 直接把 calc 结果传给下单接口，
  未过 align_order_size()。
  后果：数量不满足步进导致交易所拒单，或被截断成非预期数量成交。
  修复：qty = align_order_size(qty, lot_sz); if qty < min_sz: return
- [HIGH] B3 日内笔数熔断 ：全文未见计数逻辑。
  后果：信号抖动时可在数分钟内产生数十笔委托，手续费与滑点吞掉全部收益。
  修复：新增 MAX_DAILY_ORDERS 常量与跨日重置计数。

### 结论
CRITICAL 未通过 1 项、HIGH 未通过 1 项，判定为禁止接实盘配置。

### 复查提醒
本表通过不代表策略盈利，只代表不会因代码缺陷造成失控下单。
接实盘前另需：模拟或沙盒环境完整跑通并对账一致（CLAUDE.md §3.3）。
```

判定规则：A 组任一项不过即禁止接实盘。B、C、D 组有不过项时，须用户明示接受后方可推进。

---

## 三、审查时的取证要求

1. 每个「通过」都要指到文件与行号，写不出行号的一律记「可疑」而非「通过」。
2. 每个「未通过」都要写后果（会发生什么）与修复（改哪里、改成什么）。
3. 不得因「代码看起来有类似逻辑」就判通过；找不到即记为缺失。
