> 前置：`CLAUDE.md` §1 推断纪律、§3.4 数据不可变；写代码走 `/verified-dev`；

## 一、动手前：取证先行（硬性）

⛔ **在写下载器之前**，必须先把下列事实按 S4 取回并落到 `data/reference/`：

| # | 必须取回 | 取回方式 | 落地 |
|:--:|---|---|---|
| 1 | 端点路径、参数、分页方式与方向 | 官方文档 | 代码模块头注释（含文档 URL + 章节名） |
| 2 | 单次返回条数上限、历史深度上限 | 官方文档 + 实测 | 同上 |
| 3 | 限频规则（次数/窗口/维度） | 官方文档 | `<venue>/ingest/limits.py` |
| 4 | 时间戳单位、时区、bar 对齐（开盘还是收盘） | 官方文档 + 实测验证 | `DATA_SPEC.md` |
| 5 | 各字段含义与单位（量是基础币还是计价币？股数还是金额？） | 官方文档 | `DATA_SPEC.md` |
| 6 | 标的清单与规格（精度、最小量、步进、上市/下架时间） | 接口现调 | `data/reference/<venue>_instruments_<日期>.json` |
| 7 | 复权口径（股票）：返回的是前复权、后复权还是不复权 | 官方文档 | `DATA_SPEC.md`，⚠️ 不明确就必须问用户 |

**取回后在 Reference 清单中给出文档 URL + 章节标题，或接口路径 + 实际返回片段。**
⛔ 凭模型记忆写字段含义是本项目最高频的错误来源。

### 1.1 必须先实证验证的三件事

下载器写完、正式跑批之前，用一小段样本验证并把证据写进 `DATA_SPEC.md`：

1. **时间戳口径**：相邻 bar 的 ts 差是否恒等于周期？取一个已知的日线，
   与另一数据源或交易所网页 K 线对照，确认 ts 指向开盘还是收盘。
2. **OHLC 自洽**：`high >= max(open, close)` 且 `low <= min(open, close)` 全量成立。
3. **聚合一致**：把小周期聚合成大周期，与直接下载的大周期逐位比对。
   不一致说明至少一边的对齐方式错了。

## 二、两层存储

```
data/<venue>/
├── raw/          原始返回，只增不改（CLAUDE.md §3.4）
└── curated/      清洗后可直接用于研究，每目录配 DATA_SPEC.md
```

### 2.1 raw 层

- **原样保存**，不改字段名、不改类型、不做单位换算、不排序、不去重。
- 每个文件旁记录取回元信息：请求 URL、参数、取回时刻（UTC）、返回条数。
  可用同名 `.meta.json`，或统一写入 `data/<venue>/raw/_manifest.jsonl`。
- ⛔ 修改或删除 raw 须先问用户。重下同一区间 → 新文件加取回日期后缀，不覆盖。

### 2.2 curated 层

- 由脚本从 raw 生成，**生成脚本必须可复现**（同 raw 输入 → 同 curated 输出，逐字节）。
- 统一 schema：列名、类型、单位、时区在整个项目内一致。
- 生成脚本路径与生成时刻写进 `DATA_SPEC.md`。

### 2.3 分区与命名

```
data/<venue>/<layer>/<instrument>/<period>/year=YYYY/YYYYMMDD.parquet
例：data/okx/curated/BTC-USDT/1h/year=2026/20260819.parquet
    data/t212/curated/AAPL/1d/year=2026/20260819.parquet
```

- 标的 slug 用交易所原始标识（`BTC-USDT`、`AAPL`），⛔ 不自造映射。
- 周期用小写：`1m` `5m` `15m` `1h` `4h` `1d`。
- 文件名日期是该文件**所含数据**的日期（UTC），不是下载日期。

## 三、下载器纪律

1. **增量优先 + 断点续传**：记录每个 (标的, 周期) 已完成的最新时间戳；
   重跑只补缺失部分。⛔ 不做「每次全量重下」。
2. **主动限频**：按 `/quant-error-handling` §2.2，速率取官方上限 70%，
   ⛔ 不靠撞 429 被动退避。
3. **分页方向明确**：写清是向前翻还是向后翻，边界是开区间还是闭区间，
   并用「首尾各多取一条再去重」验证没漏没重。
4. **失败不静默**：单个标的失败不中断整批，但必须**登记到失败清单**并在结束时汇总；
   ⛔ 不允许「跑完了」而实际有静默跳过。
5. **可中断**：响应 SIGINT，落完当前文件再退出，不留半截文件。
6. 每批结束打印：标的数、时间范围、总条数、成功/失败/跳过明细。

## 四、校验（落地即校验，不通过不进 curated）

| # | 校验 | 判定 |
|:--:|---|---|
| C1 | schema 一致 | 列名、类型与约定完全一致 |
| C2 | 时间戳 | 单调递增、无重复、步长等于周期 |
| C3 | OHLC 自洽 | `low <= min(o,c) <= max(o,c) <= high`，且全部 > 0 |
| C4 | 成交量 | `>= 0`；全零段落须标记（可能是停牌或数据缺失） |
| C5 | 缺口 | 与交易日历/连续时间轴比对，缺失区间**逐条登记**，⛔ 不静默填充 |
| C6 | 异常值 | 单 bar 涨跌幅超阈值的记录单独列出，人工确认是真实行情还是脏数据 |
| C7 | 重叠一致 | 重下区间与已有数据重叠部分逐位一致；不一致即停并报告 |

**缺口处置**：登记到 `data/<venue>/curated/_gaps.csv`（标的、周期、起、止、原因、状态）。
原因分三类：非交易时段 / 交易所未提供 / 下载失败待补。
⛔ 缺口不得用插值、前向填充或邻近值填补后当作真实数据——那会直接污染回测。
研究阶段确需连续序列的，在**研究代码里**做填充并显式声明，不写回 curated。

## 五、`DATA_SPEC.md` 模板（每个 curated 目录必备）

```markdown
# <venue> <instrument> <period> 数据说明

## 1. 来源
- 端点：GET /api/v5/market/history-candles
- 文档：<URL> §Get candlesticks history
- 取回时间：2026-08-19T10:00:00Z
- 生成脚本：scripts/20260819_ingest_okx_klines.py（commit/md5）

## 2. 字段
| 列 | 类型 | 单位 | 含义 | 依据 |
|---|---|---|---|---|
| ts | int64 | UTC 毫秒 | bar **开始**时刻 | 官方文档字段表 + 实证：相邻 ts 差恒为 3600000 |
| open/high/low/close | float64 | 计价币 | 开高低收 | 官方文档 |
| volume | float64 | 基础币 | 成交量 | 官方文档；⚠️ 与 volCcy 区分 |

## 3. 覆盖范围
- 时间：2020-01-01 ~ 2026-08-19
- 条数：N
- 缺口：见 _gaps.csv，共 M 段

## 4. 已做的处理
- 去重（按 ts）、按 ts 升序、类型统一
- 未做：复权 / 缺口填充 / 异常值剔除

## 5. 已验证
- OHLC 自洽：全量通过
- 聚合一致：1h 聚合为 1d，与直接下载的 1d 逐位一致
- 时间戳口径：与交易所网页 K 线对照确认为开盘时刻

## 6. 已知问题与未证实项
- ⚠️ <逐条列出>
```

## 六、标的池

- 标的池定义放 `<venue>/config/universe.yaml`，带**选入依据与生效日期**。
- 流动性筛选标准必须写死在配置里并可复现（如「近 90 日日均成交额 ≥ X」），
  ⛔ 不允许「我觉得这几个流动性好」式的手工列表而无标准。
- **幸存者偏差**：标的池须记录历史成分变化（何时入、何时出、为什么），
  回测时用当时的成分而非今天的成分。加密尤其要注意已下架币种。
