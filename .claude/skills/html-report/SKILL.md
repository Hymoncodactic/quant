# 交互式 HTML 报告生成方法论

本 skill 是方法论指导，不绑定任何具体项目路径，适用于一切「数据加图表加结论」形态的
HTML 交付物。产出定位为对外留痕件：不用第二人称称呼读者，不引用交互过程，无 AI 署名。

语言口径（`CLAUDE.md` §2.3）：报告正文与解释卡用中文；管线脚本、模板、JS 与 CSS 中的
标识符、注释、日志与异常消息一律美式英文。

---

## 一、三件套架构（数据与呈现分离）

一份报告固定拆成三个文件，各司其职，禁止合并成单个脚本：

| 文件 | 职责 | 要点 |
|---|---|---|
| 数据管线 `make_report_data.py` | 从上游结果文件汇聚全部图表数据，输出单一 JSON | 只做汇聚与派生统计，不产生新实验结果；内置锚定断言（见 §二） |
| 模板 `report_template.html` | 完整 HTML/CSS/JS，含两个注入占位符 | 纯静态可审阅；图表构建函数逐图独立 |
| 组装脚本 `build_report_html.py` | 把模板、JSON 与 plotly.min.js 合成交付 HTML | 注入 JSON 时把 `</` 转义为 `<\/`，防止提前闭合 script 标签 |

自包含原则：plotly.min.js 从本机 plotly 包内嵌（`plotly/package_data/plotly.min.js`，
约 4.7MB），数据 JSON 内嵌，最终单文件不依赖网络。单文件 5 至 10MB 属正常。

修订版本管理：模板、数据管线、组装脚本修订时另存带版本号的新文件（例如
`report_template_v2.html`、`make_report_data_v2.py`），旧版保留作血缘。数据管线 V2
优先做成「读 V1 产物加增量追加」的形式，避免复制粘贴漂移。交付 HTML 文件名保持稳定，
在副题标注修订版本与修订内容。

## 二、数据纪律（报告可信性的根）

1. 锚定断言：管线内写定一组 ANCHORS，把报告要引用的每个关键汇总数字与其权威来源
   （裁定文档、既有结果表）的记载值断言比对，失败即退出。防止报告与结论文档数字漂移。
2. 舍入时点：中间值保留至少 2 位小数进 JSON，展示层再格式化。过早取整会让前端的
   差值计算出现 ±1 漂移，例如两个各自取整的总和相减不等于差值取整。
3. 衍生数字一致性：同一数字在 hero、图表标签、正文中的取值路径必须一致；
   正文中引用权威文档的既有数字时按原文，并在 Reference 注明。
4. 模板里禁止手打无来源数字；每个数字都要能回答它来自哪个文件的哪一列。

## 三、首屏指标：用率不用总量

首屏 KPI 卡承载的是「这套东西赚不赚、赚在哪」，因此：

1. 主指标必须是率，不是总额。年化收益率或同类率口径放第一张卡；
   总额只作为卡片副行或明细表里的一列。总额随窗口长度变化、无法横向比较，不作头条。
   头部同时给出风险调整后的比率（夏普、卡玛）与质量比率（盈亏比、胜率）；
   只报收益率不报风险的呈现是不完整的。
2. 分母写明是哪一种本金。优先用实测的最大同时占用资金（从逐笔占用区间叠加后取峰值），
   而不是计划额度，后者只反映授信而非实际投入。用哪一种都要在表下写清定义、
   给出单笔占用的最大值与均值，并在跨口径比较时并列本金列，因为不同口径本金不同，
   率指标不可脱离本金直接比较。若沿用既有文档的分母，注明出处。
   为此回测引擎需在逐笔产物中落「本笔占用资金」与入场与退出时点，否则事后无法还原。
3. 年化换算写清三要素：分子（区间累计）、区间长度（在线交易日数，无交易日按 0 计入）、
   年化基准（例如 252 交易日每年）。折算方式（简单缩放还是复利）明写。
4. 能拆就拆 α 与 β。对日收益率序列做因子回归，报告 α（年化截距）与其 t 值、
   每个 β 与其 t 值、β 的年化收益贡献、回归样本数。因子的定义与取数列要写明。
   标准误口径与报告其余检验保持一致，例如统一 Newey-West L=20。
5. β 的读法要写清楚：若策略设计上无方向敞口（配对交易、秒级持仓等），
   β 回归是对该性质的实证检验，不是收益归因。β 不显著时不得据此宣称「收益全部来自 α
   因而是真实超额」，那只是同一笔钱的两种说法。这句限定要写进报告。
6. 首屏卡片数量控制在 5 张以内，每张卡的副行给出口径（分母、窗口、费率档、显著性）。

## 四、口径一致性（同一个数只能有一个值）

一份报告里同一实体的同一指标只能有一个数。做法：取数管线只从权威口径的文件派生所有
图表块，不让任何图表继承上一版口径的数据；交付前跑跨块断言，即汇总表、累计曲线末值、
明细数组长度、率口径表四者相等。对照口径只出现在其专属章节并逐处标注。
若同一个臂在三个章节出现三个数字，即为本条未落实。

---

## 五、章节与图号编号

图号必须与文档出现顺序一致。后期插入的章节会把新图排在旧图之前，交付前按 DOM 顺序
重新编号，或把图移到正确位置，并同步图题、解释卡标题与正文里的图号引用。
交付前逐图核对一遍：图题、副题、图例、坐标轴、标注位置是否与该图实际画的内容相符。

章节编号从 1 起连续，不跳号、不用「1.5」这类插入号；层级不超过两级（N 与 N.M）。
新增章节要重排全篇编号，并同步目录、各级标题、正文里的全部交叉引用，
含解释卡、术语页、证据清单的「支持什么」字段。重排后做一次死锚点检查，
确认目录每个链接都能定位到元素，并区分「本报告的 §」与「引用外部文档的 §」，
后者不得被一起改号。

## 六、布局骨架

按序组织：固定侧栏目录（scrollspy 高亮与锚点跳转）、标题区（标题、口径徽章、日期）、
hero KPI 卡片行（4 至 5 个大数字加一行限定语）、关键结论卡（3 条以内，左色条区分）、
编号章节（口径与数据、模型与方法、主结果、归因、分层、稳健性、附注）、
结论与限定、Reference 清单（决策、依据类型、精确来源三列表）。

图表统一放 chart-card（标题、一行副题、图），紧跟一张折叠解释卡。

## 七、折叠解释卡（每图必配）

默认收起，点击展开。按钮行的构成：信息图标、标题「图 N 怎么读 · 一句话主旨」、
右侧 chevron 箭头（展开时 rotate 180 度，带 transition 过渡）。内容区用 max-height
过渡动画；按钮带 aria-expanded。

内容四段式，教学向但对外口径，不用第二人称：

1. 图例说明块（强制置顶）：图中每个 legend 条目逐条列出，含与图中颜色一致的彩色圆点
   （用 CSS 变量）、与图例逐字相同的名称、一句话含义、指向术语详解页的「详解」链接。
   读者不必离开卡片就能知道每条线与每种颜色的含义。实现上用独立的 LEGENDS 数据结构
   （图 id 映射到条目数组），渲染器自动前置到卡片内容之前，防止漏配。
2. 怎么读：横轴、纵轴、交互行为的含义；首次出现的图型给读图方法，例如 ECDF 曲线上
   任一点 (x, y) 表示样本中不大于 x 的样本占比为 y，纵轴 0.5 对应的横坐标即中位数。
3. 该图结论：这张图支持报告的哪一句话，反例或需要注意的形态是什么。
4. 数据来源：文件、列、口径注意事项，单独一行 `.src` 小字。

## 八、术语与模型详解页（体量大的解释走跳转，不塞卡片）

图例一句话讲不清的对象（实验臂定义、模型公式、统计方法、口径细节）建独立详解页，
正文与解释卡中该词以链接形式出现。要求：

1. 单文件内实现：hash 路由（`#g/<词条id>`）加全屏覆盖层，不产生第二个文件，
   保持报告自包含。词条数据集中在一个 GLOSS 结构（id 映射到分类、标题、正文 HTML、
   相关词条、出现位置），公式用等宽块呈现。
2. 双向可达（硬性要求）：
   - 正文与解释卡到词条页：`a.term` 链接，虚线下划线样式标识可点击；
   - 词条页回报告：显眼的「返回报告」按钮，关闭时恢复打开前的滚动位置；
   - 词条页之间：「相关术语」胶囊链接互跳；
   - 词条页到报告定位：「在报告中的位置」链接，点击关闭覆盖层并滚动到对应图表锚点。
3. 浏览器行为完备：hashchange 监听（后退键可沿词条链回退）、Escape 关闭、
   直接带 `#g/<id>` 打开文件时自动进入词条页。
4. 覆盖层打开时锁定 body 滚动；关闭时清 hash（用 replaceState，避免污染历史）。
5. 词条正文写法同解释卡：对外口径、不用第二人称，可含公式、采纳状态、限定语。
   每个实验臂、模型、统计口径至少一个词条。链接第一原则：读者在任何位置遇到
   不认识的名词，一次点击内必须能得到解释。

## 九、成交点标注与数据及假设专页

1. 净值或累计收益曲线上标出成交点：按方向分色分形，例如绿色上三角表示买入或开仓侧，
   红色下三角表示卖出或平仓侧；纵坐标取该日的曲线值，hover 给出该笔的损益、时刻与标的。
   成交密集时提供显示与隐藏开关，默认只标主判定臂，避免遮盖曲线。
2. 输入数据与模型假设各给一个专页，同为单文件内 hash 路由，例如 `#d/<序列>`：
   - 数据侧：真实值、模型所用预估值、两者之差的描述统计表（n、均值、标准差、
     分位数、极值、平均绝对值）与时序图、分布图；
   - 假设侧：逐条对应方法论假设编号出图，包括线性设定（解释变量散点加分档均值）、
     残差与其绝对值的自相关（含 ±1.96 除以根号 n 的界）、分布 QQ、参数递归路径、
     覆盖率对名义值。每张图在说明里点名它检验的是哪条假设编号。
   - 页内必须声明：图形与描述性统计不替代正式检验门，并链回报告里的门状态表。
   - 多个序列（多标的）各一页，互相链接，且都能返回报告。

## 十、证据溯源页（强制，与术语页并列的第二个跳转页）

报告中每一处引用到的证据都要能一次点击追到源头，用于事后的逻辑环节错误溯源。做法：

1. 建独立的证据清单页，同为单文件内 hash 路由，例如 `#e/<编号>` 与 `#e/index`。
   每条一行，含唯一编号（按类别前缀：方法论 M-、预注册与裁定 V-、脚本 S-、结果 R-、
   数据 D-、基线 B-、代码与配置 C-、纪律 K-）、类别、完整相对路径、
   「在报告中支持什么」（一句话，客观陈述，不含评价）、磁盘核实结果。
2. 磁盘核实由取数管线自动完成并写进数据文件，包括存在性、字节数、行数（文本类）、
   目录文件数、最后修改时间，必要时加 md5 前缀。清单里出现「磁盘上未找到」必须保留
   显示，不得静默删行：引用了却找不到的文件本身就是要报告的事实。
3. 正文、解释卡、Reference 表中的引用处放上标角标 `[编号]`，点击直达该行并高亮定位；
   证据页提供「返回报告」、按类别跳转、与术语页互链。
4. 证据要细到能复现单个数字：结果类给到具体文件名（含臂、窗口、费率、变体后缀），
   代码类给到文件与行号，文档类给到章节号。禁止「根据文档」「见结果目录」这类
   不指名表述。
5. 报告末尾的 Reference 表与证据页并存：Reference 表按「决策、依据类型、来源」组织，
   来源栏挂证据编号；证据页按「文件、支持什么、核实状态」组织。两者互为索引。

## 十一、客观性纪律（对外报告硬要求）

报告只写客观描述与可追溯来源，不写本方的主观判断。落地检查项：

1. 禁用评价性措辞，包括但不限于：最稳健、最易实施、价值主张、更健康、干净、天然、
   可辩护、反面教材、教训、方向正确、结论越强、问题有实际约束力、挣不到不存在的钱。
   一律改为可核对的事实陈述（数值、比值、占比、检验统计量）。
2. 引文与本方表述分离：来源文档里的定性结论若要保留，写成「引自 X 裁定 §y」并加引号；
   不得把他方的建议升格为报告的事实性小标题。
3. 每个数值可溯源；派生值显式标注为派生，例如「等于 1 减胜率」「等于张数乘面值」；
   图形读数不得当作统计结论写入正文。
4. 引用必须核对原文：引用某文档某节作为某做法的依据前，读该节原文确认它确实写了
   这件事。把「怀疑点清单」当成「既定口径授权」这类错配，属最严重的一类问题。
5. 推断显式标注：经济解释、机制归因、成因推测一律标为推断并注明未证实状态。
6. 过程性与交互性表述清除：本版补上、如实披露、我们、你、本轮按要求，全部删除。
7. 写完后做一次专项审计，可交由独立 agent：逐条列出主观表述、未标来源的数值、
   与来源不符的引用，再逐条改。自审容易遗漏，独立审计能查出引用错配这类问题。

## 十二、交互套件（按需取用）

1. 吸附动点：时间序列与曲线图 hovermode 设 `x unified`；每条线追加一个 overlay marker
   trace（`hoverinfo:'skip'`，初始 opacity 0）；在 `plotly_hover` 事件里取各 trace 在该 x
   的点为目标，在 requestAnimationFrame 里按比例插值（lerp）更新 overlay 的 y 与 opacity，
   `plotly_unhover` 时渐隐。效果是光标横坐标处沿线移动的圆点。
2. 直方图虚实动画：各 trace 初始 opacity 约 0.5 叠放（barmode overlay）；
   hover 到某臂时该 trace 目标 0.92、其余 0.22，用 rAF 逐帧 `Plotly.restyle` 过渡；
   unhover 时归位。
3. 分段控件（费率、口径、标的切换）：纯 CSS 按钮组，状态对象加重绘函数；
   重绘用 `Plotly.react` 而非重建 DOM。
4. 主题切换：颜色全部走 CSS 自定义属性（light 与 dark 两套，`prefers-color-scheme`
   与 `data-theme` 覆盖两向生效）；每个图表的构建函数注册进 RENDERERS 数组，
   切主题时全量重跑，构建函数内用 getComputedStyle 现取颜色。
5. 长时间序列加 rangeslider；表格数值列用 `tabular-nums`；
   金额用 Intl.NumberFormat 带符号格式。

## 十三、图表规范

1. 配色按 dataviz skill 执行，先读该 skill：分类色按实体固定分配、全报告一致
   （同一实体在所有图中同色）；流量图（瀑布）用增、减、水平的语义色而非实体色；
   序列数量不少于 2 时必有图例；不用双轴。
2. 结论优先的图型选择：分布对比优先 ECDF（不受分箱影响、可直读任意分位数），
   直方图作形态辅助；归因用瀑布图并把显著性直接标在增量段上；
   多臂权衡用气泡散点（x 为数量、y 为质量、面积为总量）。
3. 常见实现坑：字符串代码（例如英股代码 "0700"、合约名 "BTC-USDT"）会被当数字轴，
   须显式设 `xaxis.type='category'`；annotation 贴边会被裁切，须加 margin 或
   固定 y range 头寸；分组聚合后列名与 pandas 方法名冲突（例如 `corr`）时用下标访问；
   hovertemplate 用 `<extra></extra>` 去掉 trace 名尾巴。
4. 对照基准必须先定义可比域（2026-08-10 增补，硬性）。任何「本方法对朴素基准」类图，
   先回答该基准在哪些样本上有定义：跨结构断点（篮子重构、单位切换、口径变更、合约换月）
   的相邻两期相减得到的是口径差而非预测误差。不剔除的后果是少数几天贡献几个数量级的
   离群值，把坐标轴拉到那个量级，其余样本被压成一条线，图面呈现「差距悬殊」，
   实际是坐标轴假象。实证记录：现金差额「取昨日真实值」基准未剔除篮子重构日时
   最大误差 99,843 元、剔除后 11,362 元；剔除前后该基准与官方预估的中位分别为
   123 对 135 与 112 对 135，即真实关系是量级相当，未剔除版本给出的是错误印象。
   落地三条：(a) 基准只在可比样本上计算，剔除条件写进图注并给出剔除天数；
   (b) 横轴截到两条序列的 99% 分位并在标题注明；(c) 图下配分位数对照表，
   同时列「剔除后」与「未剔除」两行，使差异来源可见。
5. 自身分布与对比分布是两张图。要求看「A 的分布」和「B 的分布」时，除叠放对比图外，
   还要各出一张独立直方图（同一分箱以便对看），标中位与均值竖线，图下配完整描述
   统计表（n、均值、中位、标准差、P5、Q1、Q3、P95、最小、最大）。描述统计放图下表格，
   不塞进标题，标题过长会被居中裁切。均值与中位接近时两个标注会重叠，
   按二者大小关系分别设 `xanchor` 并错开 `y`。
